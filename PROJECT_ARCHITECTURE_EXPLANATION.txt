3. BACKEND & PERSISTENT DATABASE FILES (Server Infrastructure & Storage Vaults)
==============================================================================================

• /server.ts
  - Express.js backend application binding to port 3000.
  - Configures Vite development middleware (in dev mode) and static production serving from `/dist`.
  - Integrates the Google Gemini GenAI SDK with multi-model fallback routines (`gemini-2.5-flash`
    with automatic failover to `gemini-2.0-flash`).
  - Implements REST API endpoints:
    * `POST /api/auth/login`: Validates seeker/admin credentials against disk database
    * `POST /api/auth/register`: Creates new user account and hashes/stores credentials
    * `POST /api/auth/sync-credentials`: Atomically synchronizes client credentials vault to disk
    * `POST /api/users/profile`: Updates user birth chart and spiritual profile
    * `POST /api/users/save-data`: Atomically persists user palm scans, tarot sessions, and reports
    * `GET /api/database/status`: Health check returning user counts, credentials saved, and storage size

• /data/database.json
  - The physical on-disk JSON database file ensuring permanent data persistence across server restarts.
  - Contains records for:
    * `users`: Registered user account profiles
    * `credentials`: User ID, email, password, and role records
    * `userData`: Per-user activity stores (palm scans, tarot sessions, synthesized reports)
    * `notifications`: System announcements and cosmic transit alerts
    * `analytics`: System telemetry counters and usage metrics

• /src/data/dbServer.ts
  - Server-side database engine providing safe, synchronous read and atomic write operations
    to `/data/database.json`.
  - Handles initialization from seed defaults if the database file is not yet created.

• /src/database/userDatabase.ts
  - Client-side database abstraction layer managing two local stores:
    1. Account Store (`celestial_user_accounts_db`): User profile metadata and birth info.
    2. Activity Store (`celestial_user_data_db`): Isolated user activity keyed by email.
  - Automatically bridges local modifications to the backend via `/api/users/save-data`.

• /src/database/userCredentialsDatabase.ts
  - Dedicated User Credentials & Password Vault client database (`celestial_user_credentials_vault`).
  - Manages credential storage, registration sync, credential validation, and client-side JSON export.

• /src/database/consultDatabase.ts
  - Client consultation & booking database (`celestial_consult_db_v2`):
    * Manages seeker trial accounts (2 free trial video sessions per seeker)
    * Enforces anti-abuse rules (10-digit Indian phone number uniqueness and device fingerprinting)
    * Confirms bookings with attached palm/tarot scans and generates RFC 5545 `.ics` calendar files
    * Tracks session status, extensions (+10 mins), completions, and prescribed remedies

• /src/database/autoStorageManager.ts
  - Automated persistence guardian capturing background storage snapshots, verifying schema
    integrity, and facilitating full database import/export.

• /src/data/userCredentials.ts
  - Seed credentials definition (`UserCredentialRecord`) containing default administrative,
    consultant, reader, and seeker accounts for instant testing.

• /src/data/mockDatabase.ts
  - Seed database containing default user profiles, sample synthesis reports, system notifications,
    and platform analytics counters.

6. DATA ISOLATION, TRIAL SECURITY & STATE SYNCHRONIZATION MODEL
==============================================================================================

1. Multi-Tenant Seeker Data Isolation:
   - All user-generated scans, tarot sessions, and consultation records are strictly isolated
     and keyed by the logged-in user's verified email address (`userEmail`).
   - Switching accounts immediately re-indexes the dashboard and reading views to show only
     records belonging to the active user.

2. Free Trial Consultation Security & Anti-Abuse:
   - Each seeker account receives a welcome allowance of 2 free 1-on-1 video consultation sessions.
   - Fraud prevention is enforced through mandatory 10-digit Indian mobile number validation (+91)
     and browser device fingerprinting registered in `celestial_consult_db_v2`.

3. Dual-Layer Storage Resilience:
   - Client actions instantly update browser `localStorage` for zero-latency UI responsiveness.
   - Background sync hooks immediately replicate updates to `server.ts`, which atomically writes
     changes to `/data/database.json`, ensuring data survives across browser clearing and server restarts.
